## [0.1.1] - 2026-11-10

### Added (release-pipeline closure)

- **Migration SQL externalized**: all 40 SQL constants of V1..=V9 in `src/database/migration.rs` (27 UP across three dialects + 13 DOWN) externalized to `src/database/migrations/core/*.sql` (`v{n}_{backend}.up.sql` / `.down.sql`), embedded at compile time via `include_str!` — single-binary deployment, no runtime path dependency; FROZEN content byte-identical (verified 40/40 by three independent checks), `core_migration_file` dispatch and the `-- UP`/`-- DOWN` splicing unchanged.

### Fixed

- **Anthropic non-streaming response content shape**: `response_to_external` used to stuff the whole object from `message_to_anthropic` (`{role, content:[blocks]}`) into the envelope's top-level `content` field, producing the nested `content = {role, content:[…]}` object — violating the Anthropic Messages contract (`content` must be a block array), so examples reading `content[0].text` failed. After the fix the envelope is `{role: "assistant", content: [block array], …}`, with a new inline regression test locking it; the two existing assertions that locked the old shape were updated to the contract shape in sync.
- **gRPC auth-semantics documentation alignment**: `src/server/grpc.rs`, the `grpc_client` example and examples/README used to claim "GetInfo is auth-free"; the actual sdforge facade semantics are that configuring `auth_verifier` makes it a global interceptor over all methods (including GetInfo — 0.1.0 production behavior was already this). Docs/examples/tests aligned to reality in three places (the smoke test became a two-way assertion); auth-free liveness probes go through the same-process HTTP `/health`; the GetInfo auth-free whitelist is on the 0.2.0 upstream plan.
- **responses.rs log i18n backfill**: 7 warn-level raw English strings registered in Fluent (en keys/values verbatim from the originals, zero behavior change; zh aligned translation).

### Security

- **RUSTSEC-2026-0459 exemption registered** (libsqlite3-sys 0.37.0 bundled SQLite < 3.54 WAL page cache uninitialized memory, CVE-2026-119375, medium): the fixed version ≥0.39.0 is hard-blocked by upstream sqlx 0.9.0 (already the latest); registered in `.cargo/audit.toml` per a mitigation assessment of the local attack vector plus operator-hosted DBs that do not accept external .db files — upgrade and remove as soon as sqlx ships a compatible version.

### Changed

- **Error response copy**: error payloads are no longer localized at construction sites; HTTP error bodies render per locale uniformly via `user_message()`; SSE error frames and the `/v1/responses` background failure object use fixed safe copy (internal error details/anchors/upstream URLs go only to tracing, never outbound). - **`VaultError` / `GateError::Io` / `Protocol` / `Routing` / `VendorUnavailable` presentation paths**: anchor dereference is attempted first, then a generic template fallback — fixing anchor key names potentially leaking into HTTP response bodies.
- **web-search error de-sensitization**: `reqwest` transport errors keep only the class (timeout / connect failed / invalid response body / transport error); the 502 body no longer carries internal provider URLs; vault key-fetch failures likewise return only safe copy.

### Fixed

- **Difficulty half-open probe slot**: the read-only explain surface now uses the non-mutating `peek` (no longer consuming the sole probe slot); probe futures release the slot via RAII on cancellation, and only the `Probe` branch occupies it, with only half-open-state record clearing — fixing the window where admin queries/cancellations could permanently degrade the classifier.

- **`error::app` split**: `FluxweirError`'s `IntoResponse`/`user_message`/source conversions and the contract guard moved from `mod.rs` into `app.rs`; `mod.rs` keeps only types and re-exports.

- **BREAKING: structured circuit-break rejections** (`GateError` variant set extended): CB Open rejections changed from the `VendorUnavailable{vendor: "{id} (circuit open)"}` string marker to the dedicated variant `VendorCircuitOpen{vendor: <plain id>}` — the fallback triggers (`CircuitOpen`/`RateLimited`/`Http5xx`) and `is_circuit_open_error` now discriminate by variant, removing locale-dependent string round-trips; `GateErrorClassifier` does not count this variant as a CB failure (preventing half-open probe-window rejections from re-raising the counter so the breaker could never recover). ### Added

### Fixed

- **Monthly window + timezone offset reset math error (monthly+tz, HIGH)**: `Period::reset_at` previously computed "the 1st of next month" in the UTC frame — with `tz_offset_secs≠0`, monthly windows collapsed to |tz| hours at the month head (a tz=+8h monthly window flipped after just 8 hours) and tz<0 flipped early; affecting `is_expired` (wrong 429s / expired misjudgment fail-open on recovery), `period_secs` (pace-factor denominator distorted ~93×), the smart factor's `reset_secs` (always 0 = full boost) and 429 Retry-After. Fix: period math extracted into the pure-function file `src/middleware/quota_period.rs`; `reset_at`/`is_expired`/`period_secs` gained a tz parameter, and monthly windows now take the month head in the local frame then fold back to UTC (start-reset closed-loop invariant regression tests covering tz ∈ [−12h, +14h] × 12 months).

- **Quota ledger persistence and lifecycle (HIGH×2)**: ① `upsert_quota_ledger` auto-committed per row (a 30s full flush meant up to 10k fsyncs worst-case) → whole-batch single-transaction commit (same pattern as `log_requests_batch`; one row's failure rolls back the batch); ② `quota_ledger` had no cleanup path (daily windows accumulated one row per tenant per day forever, and startup restore read the whole table unbounded) → retention cleanup (hourly `DELETE WHERE window_start < now − the configured longest window`) + the same lower-bound SQL filter on the restore read side + a 10k-key refill cap (explicit warn beyond it); ③ restore column mapping's `unwrap_or_default` silently zeroed → errors surface explicitly.

- **Quota routing hot path and eviction (MEDIUM)**: ① `quota_factor_contexts` computed all candidate views before the mode decision (default off computed them per request for nothing; smart computed them twice) → one mode decision + a single views snapshot (shared across multiple candidates of the same vendor) + the off path exits the whole chain early, with filtering and scoring sharing one product; ② beyond the memory cap, per-request O(n) full-table eviction scans (holding a global lock; permanently spinning when fully active) → hysteresis watermark (after eviction, record `survivors + 1024` as the watermark; scan again only past it, amortized O(1)); ③ entry/settlement re-parsed the window set twice per request + cloned the config Vec → `QuotaState` caches the single-generation active window set (`Arc<Config>` snapshots as generation anchors; a hot reload invalidates the whole generation; zero intermediate copies on the hot path); ④ `consume`'s success path no longer materializes per-window remainder rows (Strings allocated only on rejection).
